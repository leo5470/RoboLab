**TritiumR/pps MimicGen selection comparison — 2026-11-10**

Inspected public `TritiumR/pps` main at commit `a22f9adddc3ac9827dec38381c72b7d4e9390c5f`. This is a different repository from `/tmp2/leocheng/pps`, whose origin is `leo5470/pps`. Analysis used pinned GitHub source and a CPU-only extracted-guard check. No simulator, GPU, generation or training ran.

**Finding:** the released pot/tea/weight configurations request per-subtask selection, but the bundled generator retains the same guard defect as our installed Isaac Lab. Under the inspected defaults, a source is selected once per episode and retained through the remaining subtasks. The release does not supply a working per-subtask workaround to copy.

The task configurations specify the following. In all three, `generation_select_src_per_subtask=True`, each segment uses `nearest_neighbor_object` with `nn_k=3`, and the first grasp boundary has offset `(10, 20)`; later offsets are zero.

The [base configuration](https://github.com/TritiumR/pps/blob/a22f9adddc3ac9827dec38381c72b7d4e9390c5f/IsaacLab/source/isaaclab/isaaclab/envs/mimic_env_cfg.py#L59-L77) leaves `generation_select_src_per_arm=False`. Inspection of the registered task path, generation launcher and helpers found no override for these tasks. The [generation helper](https://github.com/TritiumR/pps/blob/a22f9adddc3ac9827dec38381c72b7d4e9390c5f/IsaacLab/source/isaaclab_mimic/isaaclab_mimic/datagen/generation.py#L245-L258) loads a source dataset into a shared pool. Its [loader](https://github.com/TritiumR/pps/blob/a22f9adddc3ac9827dec38381c72b7d4e9390c5f/IsaacLab/source/isaaclab_mimic/isaaclab_mimic/datagen/datagen_info_pool.py#L274-L293) includes the input episodes rather than enforcing one loaded source per job.

The [selector](https://github.com/TritiumR/pps/blob/a22f9adddc3ac9827dec38381c72b7d4e9390c5f/IsaacLab/source/isaaclab_mimic/isaaclab_mimic/datagen/selection_strategy.py#L134-L208) scores source object poses using translation plus rotation, then samples uniformly among the nearest `min(3, pool_size)`. It does not simply choose the closest demonstration. Thus different episodes can use different humans even though an episode retains one parent.

In the [bundled generator](https://github.com/TritiumR/pps/blob/a22f9adddc3ac9827dec38381c72b7d4e9390c5f/IsaacLab/source/isaaclab_mimic/isaaclab_mimic/datagen/data_generator.py#L434-L444), selection requires an empty source index when per-arm selection is off. The loop initializes that index once at line 807, passes it to every segment at line 853, and advances the subtask at lines 1141–1143 without clearing it. The guard's normalized AST matches our installed guard exactly. Task-specific selection settings for later segments consequently do not trigger new draws under these defaults.

Reproduction artifacts are [the script](../output/pps_mimicgen_comparison_20261110/audit_selection.py), [results](../output/pps_mimicgen_comparison_20261110/audit.json), and [pinned source snapshot](../output/pps_mimicgen_comparison_20261110/source_snapshot.json). All nineteen downloaded files match their Git blob hashes. The script parses configurations and executes only three extracted guard statements with synthetic state; it does not execute the fork's complete generator. Selection gates are `[true,false,false,false]` for pot/weight and `[true,false]` for tea. Clearing the index in the counterfactual opens every gate.

The noise values above are configuration coefficients, not directly interchangeable with our position-only perturbations. For example, the [tea adapter](https://github.com/TritiumR/pps/blob/a22f9adddc3ac9827dec38381c72b7d4e9390c5f/IsaacLab/source/isaaclab_mimic/isaaclab_mimic/envs/droid_tea_ik_rel_mimic_env.py#L94-L108) perturbs the six-dimensional translation/rotation action. Boundary and interpolation settings are frame counts, not comparable durations without matching control rates.

For our plan, retain pooled nearest-neighbor selection once per episode as the closest released-PPS source-selection baseline. Implement working per-subtask reselection as the proposed diversity capability and compare it explicitly. It should not be labeled as a demonstrated requirement for reproducing the released PPS implementation. This does not settle whether unpublished generation code, overrides or historical datasets used mixed parents; that requires saved configurations and source-lineage evidence.
