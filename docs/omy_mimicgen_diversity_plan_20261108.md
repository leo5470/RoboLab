**6. Per-subtask source selection: findings and implementation plan (added 2026-11-11)**

Status: findings are from CPU analysis; the implementation below is proposed and none of it is applied. Paths are [mimicgen.py](../robolab/core/omy_teleop/mimicgen.py), [mimic_sources.py](../robolab/core/omy_teleop/mimic_sources.py), [pipeline.py](../robolab/core/omy_teleop/pipeline.py) and [final_dataset.py](../robolab/core/omy_teleop/final_dataset.py) under `robolab/core/omy_teleop/`, and `data_generator.py` / `selection_strategy.py` in the installed Isaac Lab Mimic at `.venv/lib/python3.11/site-packages/isaaclab/source/isaaclab_mimic/isaaclab_mimic/datagen/`.

*Evidence base.* A static read of the installed Isaac Lab 2.2.0 (`isaaclab_mimic` 1.0.12, byte-identical to upstream tag v2.2.0) and of public `TritiumR/pps` at `a22f9add`, plus a CPU harness that runs the real `DataGenerator`, `DataGenInfoPool` and selection strategies against a fake environment with eight synthetic sources and three subtasks. The [harness and its two result files](../output/isaaclab_mimic_selection_audit_20261111/) run as `harness.py <datagen_dir> <math.py> <label>`. The harness exercises control flow, indexing and pose transforms. It does not exercise IK, contacts, grasp stability or task success. No simulator, GPU, generation or training ran.

*Findings.*

- **The per-subtask flag alone does nothing for a single arm.** Selection needs `is_first_subtask or generation_select_src_per_subtask` (`data_generator.py:351`) and, when `generation_select_src_per_arm` is `False`, an empty stored index (`:353-354`). The index is filled at the first subtask and never cleared. In the harness, nearest-neighbor selection with `nn_k=3` over 300 episodes gave 1.0 selection calls per episode and 0/300 mixed-parent episodes with the flag on. Clearing the index before each later subtask gave 3.0 calls per episode and 297/300 mixed. The installed copy and the PPS copy behaved identically. This agrees with the [selection-guard audit](omy_mimicgen_selection_guard_audit_20261110.md).
- **Released PPS has the same outcome for every DROID task, not only pot/tea/weight.** All 38 DROID Mimic configs set the per-subtask flag and none overrides `generation_select_src_per_arm`. Under the released code each generated episode keeps one parent. Four of those configs pass `nn_k` to the `random` strategy on a later subtask, which raises `TypeError` once reselection works; the guard hides it today. OMY passes empty kwargs to `random` (`mimicgen.py:254-255`), so it is not exposed.
- **Once selection is called at a later subtask, the installed generator does the rest correctly.** The harness showed selection scored against that subtask's `object_ref`, the segment sliced with the newly selected source's own boundaries, the transform taken about the new source's reference-object pose at its segment start, and the bridge starting from the previous segment's last target with the configured interpolation count. No Isaac Lab change is needed.
- **OMY blocks reselection at three places.** The flag is hard-coded `False` (`mimicgen.py:250`). The loop builds one `selected` dict per trial and never clears it (`:485`, passed at `:489`). The production pipeline loads one source per job (`pipeline.py:98-99`, `:165-167`). The coordination-constraint path is not involved: OMY has no constraints (`mimicgen.py:264`).
- **The fixed-source options depend on the same guard.** `--fixed-source-index` and `--follow-source-schedule` work by pre-filling the stored index (`mimicgen.py:482-485`). Setting `generation_select_src_per_arm=True` removes the guard and breaks them: the guard audit measured a forced source violated in 212/300 trials. The switch must therefore clear the index, not change `per_arm`.
- **The placement bridge changes with a mixed parent.** A placement segment starts at parent B's grasp boundary, about 2 cm of lift (`grasp_index`, `mimicgen.py:107-112`), and is transformed about the container only. Its first target is B's hand pose over B's recorded object location, shifted by the bin's displacement. With one parent the bridge is zero when object and bin move together. With parents A and B it is nonzero whenever A's and B's recorded object-to-bin offsets differ, so mixed parents add low, fixed-duration transfers. This follows from the transform and was not measured on real sources. The over-bin segment start in section 3 removes it, because every parent's placement segment then begins over the bin.
- **Grasp consistency across parents is unverified.** B's placement motion assumes B's in-hand object pose, and the object is held with A's grasp. Nothing in Isaac Lab checks this. For the round pail the yaw component is irrelevant under validated symmetry; offset and tilt differences are not.
- **Selector details that matter when the switch is on.** `nearest_neighbor_object` adds translation in meters to rotation in radians with equal weights (`selection_strategy.py:188-200`), so rotation dominates, and for the yaw-symmetric pail that term is noise unless the selector sees the canonicalized yaw of section 3. At the placement subtask it compares bin poses, which reduces to bin translation when bin yaw is zero. `nearest_neighbor_robot_distance` ranks parents by the distance from the current hand pose to each parent's transformed segment start (`:211-307`), which at the placement subtask means the shortest bridge. Both sample uniformly among the nearest `min(nn_k, pool)` (`:203-208`).
- **Isaac Lab returns no lineage.** `generate_trajectory` reports the choice only through the mutated index dict. OMY records `selected[EEF]` once after the last subtask (`mimicgen.py:509`), which under reselection is the placement parent and drops the grasp parent.

*Implementation plan.* Steps A to D are CPU work and can proceed now. Step E is GPU work and stays deferred. Step F happens only if the gate in E passes.

- **A. Generator switch** (`mimicgen.py`)
  - `build_parser` (`:29-72`): add `--select-source-per-subtask`, off by default.
  - `validate_args` (`:75-96`): reject it together with `--fixed-source-index` or `--follow-source-schedule`.
  - `mimic_cfg` (`:250`): pass the switch as `generation_select_src_per_subtask`. Leave `generation_select_src_per_arm` at `False`.
